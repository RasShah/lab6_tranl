# Грамматика языка определений int / bool

## Постановка задачи

Разработать анализатор BISON+FLEX для выражений, состоящих из определений
переменных `VAR` типов `int` и `bool`. Контрольный пример:

```c
int a=1+2; bool x,z=TRUE;
```

Flex распознаёт лексемы. Bison проверяет синтаксис и создаёт узлы
абстрактного дерева. Python выполняет семантическую проверку и вычисления.
Дерево не содержит служебные знаки `,`, `;`, `=`, но все они доступны
в таблице токенов.

## Терминалы

| Терминал | Правило / лексемы |
|---|---|
| VAR | `[a-zA-Z][a-zA-Z0-9]*`, кроме зарезервированных слов |
| INTEGER | `[0-9]+`, десятичная запись |
| BOOLEAN | `TRUE`, `FALSE` |
| Тип | `int`, `bool` |
| Арифметика | `+`, `-`, `*`, `/`, `%` |
| Логика | `!`, `&&`, `||` |
| Сравнения | `<`, `>`, `<=`, `>=`, `==`, `!=` |
| Разделители | `=`, `,`, `;`, `(`, `)` |

Знак отрицательного числа распознаётся отдельным токеном `-`.
Комментарии и пробельные символы пропускаются лексером.
В файле `.y` токен идентификатора называется `IDENTIFIER`, а в таблице
токенов выводится как `VAR`.

## EBNF

`{ X }` — ноль или более повторений; `[ X ]` — необязательная часть.

```ebnf
Program     = Declaration, { Declaration } ;
Declaration = Type, Variable, { ",", Variable }, ";" ;
Type        = "int" | "bool" ;
Variable    = VAR, [ "=", Expression ] ;

Expression  = Or ;
Or          = And, { "||", And } ;
And         = Equality, { "&&", Equality } ;
Equality    = Relation, { ("==" | "!="), Relation } ;
Relation    = Sum, { ("<" | ">" | "<=" | ">="), Sum } ;
Sum         = Product, { ("+" | "-"), Product } ;
Product     = Unary, { ("*" | "/" | "%"), Unary } ;
Unary       = ("+" | "-" | "!"), Unary | Primary ;
Primary     = INTEGER | BOOLEAN | VAR | "(", Expression, ")" ;
```

В [mini.y](../files/mini.y) выражения записаны компактно через рекурсивное
правило `expression`; приоритеты задаются `%left` и `%precedence`.
Это соответствует приведённым уровням EBNF. Правила с `error` используются
только для восстановления после ошибки и не делают ошибочную программу допустимой.

## Приоритеты

От высокого к низкому:

| Уровень | Операторы | Ассоциативность |
|---|---|---|
| 7 | унарные `!`, `+`, `-` | справа налево |
| 6 | `*`, `/`, `%` | слева направо |
| 5 | `+`, `-` | слева направо |
| 4 | `<`, `<=`, `>`, `>=` | слева направо |
| 3 | `==`, `!=` | слева направо |
| 2 | `&&` | слева направо |
| 1 | `||` | слева направо |

Скобки явно задают порядок вычисления. Например, `2+3*4` равно `14`,
а `(2+3)*4` равно `20`.

## Правила типов

| Конструкция | Входные типы | Результат |
|---|---|---|
| `+`, `-`, `*`, `/`, `%` | `int`, `int` | `int` |
| унарные `+`, `-` | `int` | `int` |
| `<`, `<=`, `>`, `>=` | `int`, `int` | `bool` |
| `==`, `!=` | два значения одного типа | `bool` |
| `&&`, `||` | `bool`, `bool` | `bool` |
| `!` | `bool` | `bool` |

Тип инициализатора должен совпадать с типом переменной. Преобразований
между `int` и `bool` нет. Так, `int a=TRUE;` синтаксически корректно,
но отклоняется при семантической проверке.

Область видимости одна, глобальная. Определения обрабатываются слева направо.
Имя резервируется перед вычислением его инициализатора, поэтому
`int a=a+1;` является ошибкой использования переменной без корректного значения.
Повторное объявление запрещено, в том числе с другим типом.

`int a=2,b=a+1;` допустимо; `int a=b+1,b=2;` — нет.
Объявление без инициализации хранит значение `None` и признак
`initialized=False`. Оно не получает автоматически `0` или `FALSE`.

Границы `int` проверяются при вычислении. Литерал `2147483648`
допускается как непосредственный операнд унарного минуса для записи
`-2147483648`; положительное значение вне диапазона не допускается.

Логические операции выполняют сокращённое вычисление. Проверка имён,
инициализации и типов проходит заранее для всего выражения, включая
ветви, которые не будут вычисляться.
