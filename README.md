# Лабораторная работа № 6 — анализатор BISON+FLEX

**Язык:** последовательность определений переменных `VAR` типа `int` и `bool`.

```c
int a=1+2;
bool x,z=TRUE;
```

Консольный Python-проект с настоящими **GNU Bison и Flex**. Flex разбивает
текст на токены, Bison проверяет грамматику и строит абстрактное синтаксическое
дерево. Python запускает сборку и анализ, проверяет типы, вычисляет значения
и выводит таблицу переменных.

## Быстрый запуск

Нужны Python **3.10+**, GNU Bison **3.8+**, Flex **2.6+** и компилятор GCC
или Clang с поддержкой C11. Python-библиотеки из pip не требуются.
Установка инструментов описана в [docs/bison-flex-install.md](docs/bison-flex-install.md).

Из корня проекта:

```powershell
python main.py examples/valid/basic.mini
```

При первом запуске Python автоматически генерирует и компилирует анализатор.
На Windows автоматически ищутся инструменты в `PATH` и `C:\msys64`.
После изменения `.l`, `.y` или нативных исходников выполняется пересборка.

Программа прямо в командной строке:

```powershell
python main.py --code "int a=1+2; bool x,z=TRUE;"
```

Результат:

```text
BISON + FLEX — анализатор объявлений int / bool
Результат: OK — программа корректна.

Таблица переменных:
VAR  Тип   Значение             Позиция
───  ────  ───────────────────  ───────
a    int   3                    1:5
x    bool  не инициализирована  1:17
z    bool  TRUE                 1:19
```

В объявлении `bool x,z=TRUE;` инициализатор относится **только к `z`**.
Объявление `x` допустимо; чтение `x` в другом выражении до инициализации
считается семантической ошибкой. Отдельных операторов присваивания в языке нет.

## Возможности языка

- Несколько определений, каждое завершается `;`.
- Несколько переменных одного типа через запятую: `int a, b=2, c=b+1;`.
- Целые числа, `TRUE`, `FALSE` и ссылки на ранее инициализированные переменные.
- Арифметика: `+`, `-`, `*`, `/`, `%`, унарные `+` и `-`.
- Логические операции: `!`, `&&`, `||`.
- Сравнения: `<`, `<=`, `>`, `>=`, `==`, `!=`.
- Скобки, обычные приоритеты и левая ассоциативность бинарных операций.
- Комментарии `// ...` и `/* ... */`, пробелы и переносы строк.

`VAR` соответствует `[a-zA-Z][a-zA-Z0-9]*`: начинается с латинской буквы,
далее допускаются буквы и цифры. Регистр значим. `int`, `bool`, `TRUE`, `FALSE`
зарезервированы. Идентификаторы с `_` или кириллицей не входят в этот вариант языка.
UTF-8 в комментариях разрешён.

`int` — знаковое 32-битное целое: от `-2147483648` до `2147483647`.
Переполнение при вычислении и деление на ноль являются ошибками.
Целочисленное деление округляет к нулю: `-7/3 == -2`, `-7%3 == -1`.
`bool` не преобразуется в `int`, и наоборот.

`&&` и `||` вычисляются с сокращением: в `FALSE && (1/0 == 0)` деление
не выполняется. Проверка типов и использования переменных проходит для обеих
ветвей независимо от их значения.

Программа должна содержать хотя бы одно определение. Не поддерживаются
вещественные литералы, строки, функции, циклы и повторные присваивания.
Полная грамматика и правила типов — в [docs/grammar.md](docs/grammar.md).

## Команды

```powershell
# Явная пересборка
python scripts/build_native.py
# То же через основной интерфейс
python main.py --build

# Токены и абстрактное дерево
python main.py examples/valid/arithmetic.mini --tokens --tree

# JSON в stdout или в файл
python main.py examples/valid/basic.mini --json
python main.py examples/valid/basic.mini --output report.json

# Экспорт дерева для Graphviz; сам Graphviz для анализа не нужен
python main.py examples/valid/basic.mini --dot tree.dot
# При установленном Graphviz:
dot -Tsvg tree.dot -o tree.svg

# Запуск как Python-модуля
python -m lab6 examples/valid/basic.mini

# Справка
python main.py --help
```

Аргумент `-` включает чтение из стандартного ввода. Исходные файлы и отчёты
используют UTF-8; исходники с BOM и Windows-переносами строк поддерживаются.
Максимальный размер программы — 256 КиБ.

Коды возврата: **0** — программа корректна, **1** — ошибка в анализируемой
программе, **2** — ошибка аргументов, чтения файла, сборки или запуска.

## Ошибки

```powershell
python main.py --code "int a=TRUE;"
```

```text
Результат: ERROR — ошибок: 1.
  1:7: Семантическая ошибка: Нельзя инициализировать int 'a' выражением типа bool.
```

Анализатор обнаруживает неизвестные символы, неверные идентификаторы,
незакрытые комментарии, нарушения грамматики, повторные объявления,
несовместимые типы, неизвестные и неинициализированные переменные.
Строки и столбцы нумеруются с единицы; табуляция считается одним символом.
Текст синтаксических сообщений формирует GNU Bison на английском языке.

После синтаксической ошибки восстановление выполняется на `;`, поэтому
можно увидеть несколько ошибок за один запуск. При лексических или
синтаксических ошибках семантический анализ не запускается: дерево может
содержать только успешно разобранные части. При семантических ошибках
таблица показывает также объявления с ошибкой инициализации.

## Структура проекта

```text
main.py                       Python CLI — точка входа
files/
  mini.l                      правила лексического анализа Flex
  mini.y                      грамматика и действия GNU Bison
native/
  main.c                      запуск yyparse() и вывод JSON
  ast.h, ast.c                хранение дерева, токенов и диагностик
lab6/
  build.py                    генерация и компиляция анализатора
  analyzer.py                 Python API и запуск нативного процесса
  semantics.py                проверка типов и вычисление значений
  model.py                    результаты анализа и экспорт
  cli.py                      аргументы, сообщения и таблицы
scripts/build_native.py       отдельная команда сборки
examples/valid/               корректные программы
examples/invalid/             программы с ошибками
tests/test_analyzer.py        интеграционные тесты
run_tests.py                  запуск всех тестов
docs/                         грамматика и установка инструментов
docker/                       контейнерное окружение
build/                        генерируется автоматически
```

Поток обработки:

```text
main.py → исходный текст UTF-8 → Flex yylex() → Bison yyparse()
        ← токены + дерево + ошибки в JSON ← нативный анализатор
        → проверка типов и вычисление в Python → таблица / JSON / DOT
```

В `build/` создаются `lexer.c`, `parser.c`, `parser.h`, отчёт об автомате
`parser.output` и `analyzer_native.exe` (Windows) либо `analyzer_native` (Linux).
Bison строит LALR(1)-анализатор. Сборка запрещает предупреждения и конфликты
грамматики; C-код компилируется с `-Wall -Wextra -Werror`.
Вручную редактировать сгенерированные файлы не нужно.

## Проверка

```powershell
python run_tests.py
```

Тесты запускают настоящий скомпилированный анализатор. Проверяются все файлы
из `examples/`, результат исходного примера, операции, типы, позиции ошибок,
границы `int`, кодировки, экспорт и коды завершения CLI.

## Использование из Python

```python
from lab6 import analyze

result = analyze("int a=1+2; bool x,z=TRUE;")
assert result.success
print({symbol.name: symbol.value for symbol in result.symbols})
# {'a': 3, 'x': None, 'z': True}
```

Некорректная программа возвращает `result.success == False` и список
`result.diagnostics`. Проблемы с инструментами вызывают `lab6.build.BuildError`.

## Docker

Из корня проекта:

```powershell

docker run --rm lab6-bison-flex
docker run --rm lab6-bison-flex examples/valid/boolean.mini --tokens
docker run --rm --entrypoint python lab6-bison-flex run_tests.py

# Docker Compose
docker compose -f docker/docker-compose.yml run --build --rm analyzer
```

Для локального запуска Docker не требуется.
